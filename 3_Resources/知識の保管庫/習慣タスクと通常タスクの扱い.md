# 習慣タスクと通常タスクの扱い

## 結論

**データは分けて、表示は「日間ビューでだけ一緒に並べる」**のがおすすめ。

## 性質の違い

| 観点 | 普通のタスク | 習慣タスク |
|---|---|---|
| 終わり | 完了したら消える | 終わらない（毎回リセット） |
| 期限 | ある（遅れると「期限切れ」） | 基本なし。「今日やったか」だけ |
| やらなかった時 | 残り続けて積み上がる | その日の分は流れる（翌日に持ち越さない） |
| 見たい指標 | 残件数・期限までの余裕 | 達成率・連続日数 |
| 時間枠 | 都度割り当てる | 固定枠が多い（朝・夜など） |

## 混ぜた場合に起きやすい問題

- 週間ビュー下部の「未割り当てタスク」が毎日の習慣で埋まり、本当に動かすべきタスクが見えにくくなる
- 習慣の完了で「今週のサマリー」の完了数が膨らみ、進み具合が分かりにくくなる
- 習慣をやらなかった日に「期限切れ」扱いになり、赤い表示ばかり増える

## おすすめの構成

| 層 | 扱い方 |
|---|---|
| データ | `tasks` と `habits`（繰り返しルール）＋ `habit_logs`（日付ごとの実施記録）に分ける |
| 日間ビュー | 両方をタイムライン上に並べる（習慣は色や形を変えて区別） |
| 週間ビュー | 習慣はマス目（7日×習慣）の達成チェックだけにして、未割り当てリストには入れない |
| 今週のサマリー | 「タスク完了 n件」と「習慣達成率 %」を別々の項目で出す |

## 迷ったときの判断基準

**「やらなかったら翌日に持ち越すか？」**

| 答え | 分類 |
|---|---|
| 持ち越す | タスク |
| 流れていい | 習慣 |

「週3回ジム」のような回数目標があるものも習慣側（週単位のカウント）に入れると、繰り返しタスクとして毎回生成するより管理が楽になる。
