# 家計管理アプリ フェーズ1

要件定義書 v0.2 のフェーズ1（変動費入力 + 日間/期間合計 + ホーム画面）の実装。
Node.js 標準モジュールのみ（依存パッケージなし）。

## 起動

```bash
cd money/app
npm start        # http://localhost:4321
npm test         # 26件
```

初回アクセス時に「パスワード設定」画面が出ます。最初に設定したパスワードだけで入れ、
以降の新規登録は受け付けません（要件定義書 §7.7: 個人利用のため登録を閉じる）。
メールアドレスは使いません（本人専用のため。要件定義書のたたき台からの簡素化）。

## フェーズ1に含むもの

- 変動費の手入力（金額・カテゴリ・日付・店名・メモ）
- 日間 / 期間合計、カテゴリ別の内訳（数値）
- ホーム画面: 今日つかえる額 / 超過時は超過額（日割りしない）
- 当日の支出の削除
- 期間予算・固定費合計の手入力（固定費マスタ・自動計上はフェーズ2）
- ユーザー認証（パスワードのみ）

## 認証の仕様

| 項目 | 内容 |
|---|---|
| パスワード | 本人専用なのでメールなし。scrypt + ソルトでハッシュ化。8文字以上 |
| セッション | ランダムトークン。サーバーにはSHA-256ハッシュのみ保存、有効30日 |
| Cookie | HttpOnly / SameSite=Strict（HTTPS配下では Secure。`COOKIE_SECURE=1` で強制） |
| ブルートフォース対策 | パスワードが唯一の鍵なので重要。同一IPで15分間に5回失敗すると 429 でロック |
| CSRF | SameSite=Strict + 更新系APIの Origin 検証 |
| データ分離 | 支出・カテゴリ・設定はすべて `userId` で絞り込み |
| 旧データ | 認証導入前の `data/db.json` は最初に設定したパスワードのデータとして引き継ぎ |

**パスワード再設定機能はフェーズ1にはありません。** `data/db.json` の `users` を空にすれば
パスワード設定画面は再び出ますが、既存の支出は旧ユーザーのIDに紐づいたまま見えなくなります。
当面はパスワードを控えておいてください（再設定の仕組みは次フェーズ以降の検討事項）。
