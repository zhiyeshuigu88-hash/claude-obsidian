## 1. 概要

### 1.1 目的
「プロジェクトセカイ」(以下プロセカ)のプレイ結果を、リザルト画面のスクリーンショットを見ながら手入力で記録し、曲ごとのスコア推移やベスト記録を振り返れるようにする、個人利用のローカルWebアプリを構築する。

### 1.2 想定利用者
本人(開発者本人)のみ。マルチユーザー機能・認証機能は考慮しない。

### 1.3 利用環境
- ローカルPC上でNode.jsサーバーを起動し、ブラウザ(`http://localhost:PORT`)からアクセスする。
- インターネット接続は不要。データは外部に送信しない。

---

## 2. スコープ

### 2.1 やること
- リザルト画面の写真を見ながら、プレイ結果を手入力で記録する
- 記録した写真をアプリ内で保存・閲覧する(自動読み取りはしない)
- 記録の一覧表示・検索・ソート・編集・削除
- 曲(+難易度)ごとのベスト記録の自動集計
- 曲(+難易度)ごとのスコア推移グラフ表示

### 2.2 やらないこと(スコープ外)
- 写真からのOCR/AIによる自動読み取り(**将来拡張の候補**として3章末に記載)
- クラウド同期・複数端末での共有
- ユーザー認証・複数アカウント対応
- 1記録あたり複数枚の写真添付
- CSVエクスポート等の外部出力(将来拡張の候補)
- 複数の機器へのアクセス
---

## 3. 機能要件

### 3.1 記録の新規登録
- 以下の項目を入力するフォームを提供する
- 写真(任意)を1枚アップロードできる。プレビュー表示し、参照しながら数値を手入力する
- 保存すると `data/photos/` 配下に写真を保存し、JSONには相対パスのみ記録する
- 「プレイ日時」は初期値を本日日付とするが、過去日への変更も可能とする(後から記録する場合に対応)

### 3.2 記録の一覧表示
- 登録済みの全記録をカード/テーブル形式で一覧表示する
- 表示モードを切り替えられる
  - **全履歴モード**: すべてのプレイ記録を新しい順に表示
  - **ベストのみモード**: 曲+難易度の組み合わせごとに、スコア最高の記録のみ表示
- 曲名によるインクリメンタル検索(部分一致)ができる
- ソート機能: プレイ日時 / スコア / 曲名 の昇順・降順切り替え

### 3.3 記録の編集・削除
- 一覧から記録を選択し、内容(写真含む)を編集できる
- 削除時は確認ダイアログを表示する。削除すると対応する写真ファイルも削除する

### 3.4 曲別のスコア推移グラフ
- 曲(+難易度)を選択すると、その曲のプレイ履歴を時系列の折れ線グラフ(横軸:プレイ日、縦軸:スコア)で表示する
- グラフ内の各点をクリック(タップ)すると該当記録の詳細に遷移できる
- グラフ下に、その曲のベスト記録(スコア・ランク・最長コンボ・判定数・FC/AP有無)をサマリ表示する

### 3.5 FC(フルコンボ)/ AP(オールパーフェクト)の自動判定
入力の手間と表記ゆれを減らすため、判定数の入力値から自動計算してデフォルト値とし、必要であれば手動で上書きできるようにする。

| フラグ | 自動判定ロジック |
|---|---|
| AP (All Perfect) | Great = Good = Bad = Miss = 0 かつ Perfect > 0 |
| FC (フルコンボ) | Miss = 0 (APも含む) |

> 判定基準に認識違いがあれば、後の実装フェーズで調整可能な設計とする(定数化しておく)。

## 4. データ項目定義

| 項目名 | キー | 型 | 必須 | 備考 |
|---|---|---|---|---|
| ID | `id` | string(UUID) | 自動生成 | システム管理 |
| 曲名 | `songTitle` | string | ○ | 自由入力。既存入力値からの入力補完(datalist)を提供し表記ゆれを軽減 |
| 難易度 | `difficulty` | enum | ○ | `EASY / NORMAL / HARD / EXPERT / MASTER / APPEND` から選択 |
| クリアランク | `rank` | enum | ○ | `C / B / A / S` から選択 |
| 合計スコア | `score` | integer | ○ | 0以上 |
| 最長コンボ数 | `maxCombo` | integer | ○ | 0以上 |
| Perfect数 | `judgments.perfect` | integer | ○ | 0以上 |
| Great数 | `judgments.great` | integer | ○ | 0以上 |
| Good数 | `judgments.good` | integer | ○ | 0以上 |
| Bad数 | `judgments.bad` | integer | ○ | 0以上 |
| Miss数 | `judgments.miss` | integer | ○ | 0以上 |
| フルコンボ | `isFullCombo` | boolean | 自動計算(上書き可) | 3.5節参照 |
| オールパーフェクト | `isAllPerfect` | boolean | 自動計算(上書き可) | 3.5節参照 |
| 写真パス | `photoPath` | string | 任意 | `photos/{id}.jpg` 形式 |
| プレイ日 | `playedAt` | date (YYYY-MM-DD) | ○ | 初期値は当日 |
| 作成日時 | `createdAt` | ISO8601 datetime | 自動 | システム管理 |
| 更新日時 | `updatedAt` | ISO8601 datetime | 自動 | システム管理 |

### JSONサンプル
```json
{
  "id": "7f3c9a2e-1b4d-4e2a-9c3f-1234567890ab",
  "songTitle": "ワンダーランズ×ショウタイム",
  "difficulty": "MASTER",
  "rank": "S",
  "score": 987650,
  "maxCombo": 1203,
  "judgments": { "perfect": 1180, "great": 20, "good": 3, "bad": 0, "miss": 0 },
  "isFullCombo": true,
  "isAllPerfect": false,
  "photoPath": "photos/7f3c9a2e-1b4d-4e2a-9c3f-1234567890ab.jpg",
  "playedAt": "2026-07-10",
  "createdAt": "2026-07-10T21:15:00+09:00",
  "updatedAt": "2026-07-10T21:15:00+09:00"
}
```

## 5. 画面構成

| 画面 | 概要 |
|---|---|
| ① 一覧画面(ホーム) | 記録一覧、検索・ソート・表示モード切替、新規登録ボタン、各記録から編集・削除・グラフ画面への導線 |
| ② 登録・編集フォーム | 写真アップロード+プレビュー、各種数値入力、FC/AP自動判定表示、保存・キャンセル |
| ③ 曲別グラフ画面 | 曲(+難易度)選択、スコア推移グラフ、ベスト記録サマリ、履歴リスト |

画面遷移イメージ:
```
①一覧画面 ──新規登録─→ ②登録フォーム ──保存─→ ①一覧画面
①一覧画面 ──編集────→ ②編集フォーム ──保存─→ ①一覧画面
①一覧画面 ──曲選択──→ ③グラフ画面 ──戻る──→ ①一覧画面
```

## 6. 技術構成

| 区分 | 採用技術 | 理由 |
|---|---|---|
| フロントエンド | プレーン HTML / CSS / JavaScript(バンドラー不要) | 依存最小限、Claude Codeでの実装・保守がシンプル |
| バックエンド | Node.js + Express | ファイルの読み書き・写真アップロードを安定して処理 |
| 画像アップロード処理 | multer 等(Expressミドルウェア) | multipart/form-dataの受け取り |
| データ保存 | ローカルJSONファイル(`data/records.json`) | サーバー・DBインストール不要、可搬性が高い |
| 写真保存 | ローカルファイル(`data/photos/`) | JSON肥大化を防ぐため画像は別ファイル管理 |
| グラフ描画 | Chart.js(CDN読み込み) | 軽量で追加ビルド不要。折れ線グラフの実装が容易 |

### ディレクトリ構成案
```
pjsk-score-tracker/
├── server.js              # Expressサーバー、APIルーティング
├── package.json
├── data/
│   ├── records.json       # 記録データ本体(配列)
│   └── photos/
│       └── {id}.jpg
├── public/                 # 静的配信フロントエンド
│   ├── index.html           # 一覧画面
│   ├── form.html            # 登録・編集フォーム
│   ├── graph.html           # 曲別グラフ画面
│   ├── style.css
│   └── app.js
└── README.md
```

### API設計案

| メソッド | エンドポイント | 概要 |
|---|---|---|
| GET | `/api/records` | 全記録取得 |
| POST | `/api/records` | 新規登録(写真含む、multipart/form-data) |
| PUT | `/api/records/:id` | 記録更新 |
| DELETE | `/api/records/:id` | 記録削除(写真ファイルも削除) |
| GET | `/photos/:filename` | 写真ファイル配信(静的ファイル) |

> 個人利用でデータ件数も少ない想定のため、一覧取得は全件取得しフロント側でフィルタ/ソート/グラフ集計を行う設計とする(APIをシンプルに保つため)。

## 7. 非機能要件

- **プライバシー**: すべてのデータ(写真含む)はローカルに保存し、外部送信は一切行わない
- **オフライン動作**: インターネット接続なしで動作すること(ただしChart.jsのCDN読み込みのみ要検討 — オフライン運用を重視する場合はローカルにライブラリを同梱する)
- **対応ブラウザ**: 最新のChromeを主対象とする
- **データ保全**: `data/records.json` を手動コピーすることでバックアップ可能な構成とする(自動バックアップ機能は本バージョンでは対象外)
- **入力バリデーション**: スコア・コンボ数・判定数は0以上の整数のみ許可。曲名・ランク・難易度は必須項目としてフォーム側で保存前チェックを行う
